# Паспорт: Тимбот-агент (TimBotAgent)

Документ для вставки в ChatGPT. Цель: ChatGPT пишет **промпты и ТЗ для Форжа**, который правит код онбординга Тима в репозитории Island.  
**Не путать** Тима с Bloom (`@bloom26bot`) — это разные продукты.

| Поле | Значение |
|------|----------|
| **Имя персонажа** | Островёнок **Тим** |
| **Продукт** | Веб-онбординг IslandDream.ru (`/tim/`) |
| **Роль ChatGPT (этот паспорт)** | **Тимбот-агент** — формулирует задачи, промпты для Компаса (картинки), критерии победы; **не** пишет код в прод |
| **Роль Cursor (Форж)** | Lead-разработчик: `sites/tim/**`, деплой, bump версий |
| **Роль Макса** | Product Owner: утверждает экраны, тексты, ассеты, порядок шагов |
| **Дата сборки паспорта** | 2026-10-25 (по состоянию репо / README Tim) |

---

## 1. Кто такой Тим

- Маскот **Острова исполнения желаний**: зелёные «листовые» волосы, дружелюбный, на фоне острова/пляжа.
- **Не** Telegram-бот. **Не** отдельный backend-сервис.
- Это **мобильный веб-флоу** знакомства → мечты → регистрация → соцсети → PWA/ЛК.
- Визуал: **готовые сцены** (baked PNG/WebP/JPEG) + HTML/CSS поверх. Форж **не двигает** фигуру Тима внутри картинки — подгоняет UI под жесты/руки.

## 3. Роли команды вокруг Тима

```
Макс (PO)  →  Тимбот-агент (ChatGPT)  →  промпт/ТЗ  →  Форж (Cursor)
                    ↑                              ↓
```

| **Bloom** | Марафон в Telegram | Онбординг Тима |

## 4. Текущий happy-path (факт кода, 2026-10)

Источник истины: `sites/tim/README.md` + `tim-fsm.js`.

```
1 Знакомство      имя + город → «Познакомиться»
2 Видео           presentation.mp4 → «к Мечтам!»
3 Витрина мечт    по одной + «+» / удаление → «Отправить N мечт Тиму»
4 Аккаунт         ФИО (отчество необяз.), телефон, пароль → POST /register
5 Соцсети         MAX / TG / VK / WA / Mail → PATCH contacts + POST /dreams
6 Резюме          PWA / группа ВК / «остаться в браузере» → ЛК /index.html
```

### Старт с корня сайта (`/`)

По CHANGELOG v405 / прод-логика в `index.html` (коммит маршрутизации):

| Состояние | Куда |
|-----------|------|
| Есть `savedUser` | Сразу ЛК |
| Был зарегистрирован (`island_registered=1`), сессии нет | Окно входа |
| Нет аккаунта | `/tim/` |
| Черновик знакомства `tim_onboarding_v1` | Продолжить с того же экрана (если ключ ещё пишется в текущей сборке — сверять код) |

На `/tim/` при `savedUser` без `force=1` — редирект в ЛК.

### API на пути

- `POST /register`, `POST /login`
- `PATCH /users/me` — контакты (telegram, vk, …)
- `POST /dreams` — `status_id: 2` («Сейчас»), `is_public: true`
- Черновики в `localStorage`: `tim_contact_channels`, отчество, корзина мечт; ключи PWA: `tim_pwa_offer_done`

### Legacy в коде (не основной путь)

Экраны `fio`, `pwa` (алиас 6), 7 (витрина), 8 (confirm-сцена), 9 (успех) — могут остаться для отладки/`?screen=`, но happy-path их обходит.

**Важно:** AI-парсер мечт из текста **убран** из онбординга. Витрина — строго ручной ввод по одной мечте.

## 5. Визуальные правила (для промптов Компасу и ТЗ Форжу)

### Artboard

- Канон сцен: **1080×2400**
- Stage в браузере: max **430px** ширина, scale **только по ширине**
- Фон body: небо `#6eb8e8` (не «песочная страница»)

### Жёсткие запреты

1. **Не интерпретировать дизайн.** Нет ассета / невозможно совпасть с макетом → **стоп и вопрос Максу**, не «улучшать».
2. Не добавлять экраны, поля, ссылки, карточки без решения Макса.
3. Не подключать `Images/Тим/` в runtime — только `sites/tim/assets/`.
4. Карточка `.tim-card` — **без** белой/стеклянной подложки (правило `tim-deploy-ui.mdc`); поля могут быть полупрозрачными сами.
5. Не двигать Тима внутри PNG — двигать HTML под руки/лицо.
6. Speech-bubble **не закрывает лицо** Тима.
7. Фейковый status bar (9:41…) не рисовать.

### Пайплайн картинок

```
Компас → Images/Тим/inbox/
       → отбор → Images/Тим/candidates/
       → Форж ресайз/lite/webp → sites/tim/assets/v2/
       → inbox очищается
```

Промпты-шаблоны: `Images/Тим/prompts/prompt_*.txt`  
(пример: `prompt_scene_account_fix.txt` — лицо не перекрывать, без песчаной полосы).

### Ключевые ассеты v2

| Файл | Экран |
|------|--------|
| `scene_01_welcome_*` | 1 |
| `scene_02_video_*` | 2 |
| `scene_03_dream_*` | 3 |
| `scene_account_*` | 4 + 5 + login |
| `scene_04_confirm_*` | legacy confirm |
| `icon_*_dream*`, `plaque_vitrine_dreams` | витрина |
| `fin/15.png` + bubble `20.png` | резюме / PWA |
| `fin/10.png`, `fin/22.png` | tagline / табличка (где ещё используются) |

## 6. Правила деплоя Tim (Форж)

После правок `sites/tim/**` — **сразу** commit → push → SSH pull + `docker compose up -d --build`, **без** ожидания фразы «Деплой», если Макс не сказал «не деплой».

Синхронно bump:

1. `.app-version` в корневом `index.html`
2. `.tim-build` в `sites/tim/index.html` (тот же номер)
3. `?v=` у css/js Tim

Макс сверяет крошечный номер справа внизу на `/tim/`.

## 7. Чем Тимбот-агент помогает Максу

Писать для Форжа:

1. **Критерий победы** одной фразой («на экране 3 кнопка X делает Y»).
2. **Scope:** какие файлы (`tim-fsm.js` / `assets.js` / css / какой PNG).
3. **Что не трогать** (другие экраны, Bloom, ЛК).
4. **Промпт Компасу** в формате существующих `prompt_*.txt`.
5. **Smoke:** URL с `?force=1&screen=N`, что проверить глазами.
6. **Вопросы Максу**, если есть развилка (А/Б/В буквами).

Не писать:

- Полный перепис FSM «с нуля» без нужды.
- Новые фичи «голосом / файлом» (в макетах disabled — не реализовывать).
- Telegram-логику Bloom в контексте Тима.

## 10. Связь с остальным Островом

- После Тима пользователь попадает в **ЛК** (`index.html`) — мечты, шаги, дневник, витрина, бадди.
- Мечты с Тима сразу в статусе **«Сейчас»** (`status_id=2`), публичные.
- Витрина ЛК и витрина Тима — разные UI; общая сущность — таблица `dreams`.
- Социальная **Лента** (проектируется отдельно) ≠ онбординг Тима.
